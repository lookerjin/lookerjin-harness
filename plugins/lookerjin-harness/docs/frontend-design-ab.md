# Frontend Design 集成与配对试验

2026-10-25。决定：将固定版本作为独立、可选的本地 UI 专家加入 Marketplace；Harness 仍为 15 个 Skill。保留原技能及许可证字节，不引入 hook、MCP 或后台服务。插件位置为 `plugins/frontend-design`，来源与指纹由其 `SOURCE.json` 记录。本次没有将其他 UI 候选一并加入。

查看 [可交互的两份原始页面](frontend-design-ab.html)：下载后用浏览器打开，切换启用/未启用与视口宽度，可实际选择课程、修改人数和提交本地模拟表单。页面按原始产物嵌入，没有为了比较修饰基线。原始指标、版本映射、执行者记录、独立评审与控制者复验见 [frontend-design-ab.json](frontend-design-ab.json)。

## 比较方式

基线为 `e976555` 的 Harness；候选仅增加 9,390 字节的 Frontend Design 正文及许可证。每个案例使用相同已提交项目快照、相同自然用户请求、同一环境与默认继承模型配置。技能放入各自项目的 `skills/` 供独立执行者发现；没有把评分标准、版本身份或另一份结果提供给执行者。

新页面：为一个社区陶艺工作室制作课程预约页面，固定课程、价格、时间、余位、地址、营业时间和模拟边界；设计方向由执行者决定。小修：已有账户表单在无效提交后未聚焦错误摘要，只修交互，保留视觉和文案。两组标签轮换，评分在运行前固定。

四个独立执行会话完成后冻结产物。另一个未见版本身份、执行日志或父 Agent 偏好的判断者检查两份新页面各自桌面/手机截图及源码。控制者再用同一套 Playwright 检查复验，而不是比较执行者各自的“10 项通过”和“38 项通过”。单次配对有随机性，不是统计显著性实验；共享文件系统也不是安全隔离或严格双盲。

新页面候选自报查看了 17 个技能元数据，文件核对实际为 16 个；原始自报保留，报告使用实际数量。四个执行区的技能内容指纹均未变。评审只看了中性标签产物，之后才揭示新页面 maple=未启用、willow=启用；小修标签相反。

## 安装与遗漏项处理

实际使用 Codex CLI `0.159.0-alpha.3`，建立只含此插件的临时 Marketplace，依次执行 marketplace add → plugin add → plugin list → 读取安装缓存。CLI 确认 installed=true、enabled=true、版本 0.1.0；安装后正文仍为 9,390 字节，SHA-256 与固定原文相同，两个许可证存在，hook 配置为零。随后只移除本次测试插件及测试 Marketplace，列表恢复为空。仓库的真实 Marketplace 保留新成员；这不是宣称用户桌面客户端已经安装或菜单已显示。

实际查出并处理：

- Help 只扫描 Harness 邻接技能，会漏掉独立专家：现在按问题查宿主已有技能元数据或用户指定的 Marketplace 资源，仍避免全机扫描。
- 本地 Marketplace 校验只确认 manifest 存在：负对照证明损坏 JSON 也被接受。现在核对 JSON 对象、名称一致性、声明技能目录、空目录和路径越界；新增 9 个分发测试并接入 CI。它仍是引用检查，不冒充完整宿主 schema 验证。
- 仅截图目测会漏掉实际对比度问题：UI 验收明确包含渲染前景/背景、辅助小字和占位文字；保留自动工具无法判断的项目。
- 执行者自报的通过数与能力数量不能直接计分：以共同控制者复验、实际文件事实为准，历史自报不静默改写。

仍未充分覆盖：更多行业/设计风格和模型重复采样、真实屏幕阅读器与真机、Safari/Firefox、原生移动端、用户桌面客户端自动选路和菜单刷新、真实模型费用。当前结果支持可选接入及继续试用，不支持默认所有 UI 任务强制调用或宣称普遍节省成本。
