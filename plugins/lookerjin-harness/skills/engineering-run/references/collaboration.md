# 双向协作契约

Agent 可以主动向用户提出行动请求。优先选择信息增益高、双方总成本低的方式，不要求先证明自己完全做不到。读取仓库、查可用工具能轻易获得的事实由 Agent 自己完成。

每次请求只说明：目的 / 用户最小动作 / 需要返回什么 / 阻塞哪些 Unit / Agent 同时继续什么。区分三类：

- 决策：用户目标、偏好或不可逆取舍。用 [Decision Dialogue](../../decision-dialogue/SKILL.md)，给推荐与后果。
- 观察或操作：真实设备交互、受限账号内查一个状态、主观体验、线下动作。给具体步骤、观察点与返回格式；不索取密码或令牌，不让用户搬运整个仓库。
- 授权：确实未授权的外部副作用。先准备具体可审查产物，说明动作和影响；已有授权不重复询问。

例如：请在手机上打开当前预览，旋转屏幕后点提交，返回按钮是否可见与是否出现重复记录；这阻塞移动端验收，Agent 同时完成 API 回归。

请求是待办依赖，不是全任务停止。等待时推进独立 Unit；需要回答的分支保持 blocked，超时或沉默不是同意。低风险、可逆且允许自行判断的偏好可明确假设后继续；必需输入/授权不能用假设代替。

回答到达后更新受影响决定、验收或观察记录，重新计算就绪项。不要重复询问已解决的问题。人的观察属于相应入口证据，注明观察者、条件和时间，不能伪装为自动化测试。

默认使用当前客户端的原生问答/表单。只有重复操作确实受益时才生成项目本地向导，先实跑最小步骤；向导不保存秘密、不默认执行发布动作，也不替代权限系统。
