# 自适应六阶段

阶段是要回答的问题，不是必须生成的文件。已有可靠答案就跳过；跳过前期阶段不跳过验收和已有项目质量门禁。入口与回退由当前事实决定，不按固定顺序计数。

| 阶段 | 进入条件与具体方法 | 退出条件 / 下一步 |
|---|---|---|
| Brainstorm | 目标、用户价值或范围存在实质歧义；查已知事实，再用 Decision Dialogue 处理当前可回答的关键决定 | 目标、非目标、成功现象足够清楚；剩余假设有成本可控的验证方式 |
| Design | 存在多个实质结构选择，或跨模块所有权不明；System Understand 追入口、状态和约束，Design Explore 用同一标准比较少量不同方案；先实验最危险假设 | 选定边界、接口、失败行为和可验证方案；只有需要保留动机的决定写入已有 ADR |
| Plan | 修改有依赖、迁移步骤、多人写入或跨会话成本；纵向拆 Unit，列完成条件、依赖、写入范围、验收与验证入口；先选代表性 pilot | 下一可执行 Unit 明确，关键依赖无环；小改可直接在会话中表达一步计划 |
| Execute | 有足够目标与上下文；小步实施，每步有可观察结果；遵守文件/实例所有权，检查真实调用者及配置引用 | 产生可验收切片就进 Verify；未知机制交回调查，不靠连串猜修 |
| Verify | 已有待证明的行为或假设；运行实际入口、核对副作用，检查失败路径和集成路径；按证据判定 | 实现错回 Execute；模型/方案错回 Design；任务范围错回 Brainstorm；证据完整才 Ship |
| Ship | 任务关键验收、项目门禁和实际 diff 评审满足；核对最终产物与验证基线，确定已获授权的交付动作 | 达到约定交付状态并报告证据和边界；外部阻塞时保留可交接产物，不能声称目标全完成 |

## 按风险裁剪

- 已知局部小改：Execute → Verify → 必要的交接；不生成设计文档、计划文件或讨论轮次。
- 不熟悉的行为变化：Design / Plan → Execute ⇄ Verify → Ship；目标不明才补 Brainstorm。
- 架构迁移：先固定兼容性基线，Design → Plan → 逐 Unit Execute ⇄ Verify → 集成 Verify → Ship。
- 只读调查：围绕问题采证和核实结论，交付解释；不强行创建产品修改。
- 用户只要方案或原型：在约定产物得到验证后交付，不自动继续生产实现。

提高保证强度的信号：数据迁移、权限/资金、并发状态、外部兼容性、不可逆操作、陌生系统。相应增加失败注入、独立审查、回滚/兼容路径或形式化检查；不是增加六份文档。降低流程重量不能降低用户验收、测试阈值、安全与项目既有门禁。

## 反馈重新进入

CI、运行告警、用户报告先保留原始现场，判断它针对哪个产物/环境。明确回归走 Bug Fix；目标变化回 Brainstorm；配方漂移走 Verification Run 的维护路径。发布后反馈不自动扩大权限或触发 Harness 演化。
