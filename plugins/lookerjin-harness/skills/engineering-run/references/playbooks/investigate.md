# Investigate

状态：Ground → Evidence → Explain。产出解释或判断，保持只读，不修产品代码。

1. 用 [system-understand](../../../system-understand/SKILL.md) 找到入口、关键状态和边界。只回答当前问题；涉及设计动机时按需追溯历史。
2. 对存在实质分歧的结论列出竞争性解释，先选最有区分度的只读检查。允许运行隔离的观察性实验；先确认其不会修改目标数据或产生外部副作用。
3. 引用直接证据，区分已确认、推断、假设与未知。证据不足时给窄结论，指出缺失节点。
4. 输出当前最可靠的解释、实际影响、适用边界和必要的下一步。若用户随后要求修复，再路由到 Bug Fix 或 Feature。

退出门槛：核心判断有可追溯证据，或明确报告无法确认的部分。发现 bug 不等于获得修改授权。
