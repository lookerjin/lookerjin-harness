# Long Run

状态：Done Predicate → Units → Pilot → Execute → Verify → Continue / Stop。

1. 把整体完成条件写成可检查的行为或数量，明确范围、预算、依赖与已有外部授权。“一直做”不自动授予 push、PR 或部署权限。
2. 拆成有验收与验证方式的 Units。每个 Unit 指定主 Playbook、目标、写入范围、必要上下文、预算与报告位置；复用项目既有 Issue、任务文件或当前计划，不新增状态系统。
3. 先让一个代表性 Unit 走完执行、验证和汇总，修正有问题的任务契约与配方，再扩展批量。
4. 按依赖执行。仅在当前客户端允许且写入范围独立时并行；共享文件、分支、实例或数据必须隔离或串行。没有子 Agent 时由当前 Agent 逐项完成。
5. 逐项核对实际产出、验证和证据。主 Agent 必须判断报告，不机械接受子 Agent 的“完成”。受影响的集成路径也要验证，Unit 绿色不等于整体完成。
6. 检查 Done Predicate，成立才结束。证据不足时补检查；明确阻塞或预算耗尽时保留已完成结果，记录下一动作和未完成项，清理自己的临时运行资源。

退出门槛：完成条件和关键集成验收已验证；否则明确标为部分完成或阻塞。不要创建多日调度器、ledger、队列或递归协调树。
