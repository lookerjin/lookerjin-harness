# Refactor

状态：Pin Behavior → Target Shape → Transform → Equivalence → Review。

1. 找到受影响调用者和现有行为契约，包括错误、顺序、副作用和公开接口。先运行已有行为用例；覆盖缺口影响本次判断时补最小 characterization 或记录可回放的输入输出基线。
2. 说明目标结构和它降低的实际维护成本。存在关键所有权或模块选择时使用 Design Explore；局部移动不展开架构比赛。
3. 分小步变换并保持基线有效。检查所有真实调用点、字符串引用、配置和文档；外部兼容性按项目约定处理，不擅自删掉仍在使用的公开接口。
4. 对原输入复跑新实现，比较行为和副作用；项目真实入口受影响时从该入口检查等价性。编译与 lint 不等于行为保持。
5. 用 Change Review 检查意外行为变化。发现新功能或 bug 时单独说明并重新路由，不静默混入。

退出门槛：声明的行为契约保持，目标结构改善有具体依据。证据不足的部分标为未验证。
