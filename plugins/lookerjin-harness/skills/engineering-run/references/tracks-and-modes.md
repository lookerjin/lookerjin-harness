# Track 与 Mode

Track 决定验收语义，Mode 决定执行方式，两者都不重定义生命周期。

| Track | 方法与退出条件 |
|---|---|
| Feature | 追踪真实入口与状态；明确输入、输出、错误和副作用；先完成可运行的纵向切片，再扩展。关键行为与集成验收得到证明 |
| Bug Fix | 由 [Root Cause Debug](../../root-cause-debug/SKILL.md) 拥有复现→竞争假设→区分实验→机制→最小修复的方法；保存原失败证据，从同一入口与可比条件复验。不能复现就明确不确定性 |
| Refactor | 固定调用者、错误、顺序、副作用和接口的行为基线；必要时补 characterization。大迁移按扩展兼容入口→迁移真实调用者→检查剩余引用→收缩旧入口推进；每步可验证、可回退。架构级重构先定义模块职责和依赖方向，不能降格为改文件名 |
| Investigate | 只读追踪调用链，区分事实、推断、假设、未知；隔离观察实验不能修改目标数据。交付有来源的解释和边界；发现 bug 不等于获得修复授权 |

| Mode | 使用条件与执行方法 |
|---|---|
| Prototype | 为具体决定做低成本探针，先定预算、观察指标与弃用条件。隔离实验，比较实际运行结果；原型也可直接是交付物。转生产时重新按目标验收，不把探针自动宣称生产就绪 |
| Long Run | 明确整体完成条件、资源预算与停止条件；拆 Unit，先 pilot 全链路，再推进就绪集合。每个 Unit 复核证据，最后验证集成；中断按连续性恢复。预算耗尽只改变完成状态，不降低门槛 |
| Parallel | 当前环境允许且任务独立时使用；写入文件、分支、服务实例与数据必须有所有者。共享写入先隔离或串行，合并后验证集成。没有并行工具时顺序完成 |
| Subagent | 当前宿主与用户规则允许时按能力委托；输入目标、必要上下文、范围、禁止项、验收、验证、预算和报告位置。回收原始证据并独立复核，不能凭“完成”收单；没有子 Agent 能力就由当前 Agent 执行 |

模式可组合，但不能因为长任务就自动多 Agent，也不为每个 Unit 递归建立协调层。任何模式都不会扩大 commit、push、部署或对外沟通的授权。
