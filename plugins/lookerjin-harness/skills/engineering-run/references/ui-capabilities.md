# UI 专家能力接入

UI 是能力类别，沿用工程六阶段；不另建第二个生命周期。当前说明约束如何选择和验收已可用的能力，不代表已经安装任何专家插件。

| 当前需要 | 选择与交付 |
|---|---|
| 新页面或视觉方向 | 设计专家：用户任务、真实内容、视觉约束、关键状态、响应规则；已有品牌与组件优先。方向未定且影响实质选择才请用户比较 |
| 已有组件的小修 | 直接实现相关状态或布局；保留既有视觉语言，不强制重做设计系统或全页审查 |
| 交互、组件实现 | 当前技术栈专家与现有组件库；跨页共享状态、键盘/触屏入口、加载/空/错误/权限状态按实际影响补齐 |
| 界面质量检查 | 适用的 UI 审查能力加现有 Verification Run；静态规则、渲染观察、真实操作分别报告 |

每次只加载当前能力及必要资料。已有熟悉组件无需检索整套样式库；窄问题优先查具体规则。外部检索结果先核对语义、平台和适用版本；泛化的“焦点可见”不能充当“弹窗关闭后焦点恢复”的答案。无命中时明示缺口，不把默认推荐写入项目事实。

专家接收当前目标、目标页面/组件、现有设计约束、验收入口与预算；返回变更、取舍、实际证据和未覆盖项。用户只需自然语言描述任务，通用 Help 负责解释入口；不要求记一套 UI 子命令，不同时加载多个重叠设计总管。

验证复用已有验收 ID：在实际交付尺寸下渲染；从真实入口操作；检查对应内容/状态/副作用。相关时覆盖键盘与焦点、窄屏溢出、对比度、减少动画偏好及失败恢复。截图可评估视觉，但不证明按钮工作；静态工具无告警也不证明交互或审美正确。没有可运行界面时保留未验证状态，真人实机观察更有效时按协作契约给出具体步骤。

接入前按 Dependency Evaluation 核对许可、固定版本、完整资源路径、安装副作用与运行成本。纯说明、规则检索、原生检测器和浏览器运行成本分开测。拒绝自动安装 hook、全库后台扫描及每次启动加载全部资料。独立专家依赖由 Marketplace 管理，保留其许可证和来源，不复制为自有实现。
