# Behavioral Evaluation Protocol

## 控制区

先固定：版本内容指纹、项目 commit、任务请求、模型与推理预算、工具权限、运行上限、验收与否决条件。一次比较尽量只改变 Skill；若比较整套 Harness，明确这是能力包变化，不能归因到某条指令。

评分标准必须观察结果，例如“原始 CLI 失败路径变为正确输出”“清理后仍能读到证据”“未产生未授权远程操作”。自报“遵循了流程”、读过文件的数量和文档长度不单独计分。

控制区的 rubric、版本映射、预期答案与其他执行者结果，不进入任务目录、提示或继承上下文。项目本来存在的测试可以保留；不要为盲评机械删除所有含 test/eval 的正常项目文件。

## 执行者

为各执行者提供相同自然任务、同一项目初始快照、指定 Skill 和相同资源。提示只替换实际目录，不追加诊断结论；每个执行者只写自己的目录。

上下文隔离不等于文件系统访问控制。共享工具环境中执行者可能访问其他路径；有真实 sandbox 能力时使用，没有时限制任务范围并注明评估弱点，不能声称安全隔离或严格双盲。

记录原始请求、实际产物、退出状态、可用的当前运行轨迹和验证证据。不要要求模型暴露内部推理。拿不到轨迹就写 unknown；不从执行者摘要推断它确实运行了命令。

外部状态、端口、数据目录、缓存与凭证应独立或按相同前提重置。不得通过一次真实生产操作检验授权规则，用隔离夹具或只读迹象判断。记录失败与清理，保留证据。

## 判断者与负责人

执行者完成后再评分，避免边写边评。判断者只看到中性标签、相同 rubric、原始产物与必要任务上下文，不看到版本身份、模型身份或父 Agent 的偏好。

同一判断者对两份产物使用同一尺度，每项给证据与 [execution-contract](../../engineering-run/references/execution-contract.md) 的状态。独立判断者与负责人分歧时，定位具体事实或 rubric 歧义，不能用平均票数消除分歧。

负责人复核可重跑的验收、实际 diff 与副作用。先完成盲判，再读取版本映射。依赖条件缺失、执行者退出或上下文泄漏时，把相关结论标为不确定；不删除掉队结果后只报告成功者。

## 采样与建议

先跑一对代表性任务，确认请求、启动和证据采集可行，再扩大。至少覆盖正触发、负触发和关键失败路径；模型随机性明显时做重复配对，轮换标签或运行顺序。单次胜出只能说明本次案例，不支持整体优越性。

报告：

- 比较对象、项目快照、请求与环境是否相同。
- 预先固定的评分标准、否决条件与已知污染。
- 每个中性标签的实际行为、证据、失败、未运行项和耗时/成本（只有真实记录时填写）。
- 判断者结论、负责人复核与分歧处置。
- 揭示映射后的逐案例变化及适用边界。
- 建议：保留候选、修改后重试、拒绝或无法判断。

关键失败不能被总分盖过；`INCONCLUSIVE` 不计为成功。是否长期晋升还需 Harness Evolve 的重复证据门槛。
