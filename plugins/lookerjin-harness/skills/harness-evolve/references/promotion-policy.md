# Harness Promotion Policy

portable core 只保存已经通过真实开发证明有复用价值的东西。

## 可以提升的条件

对从摩擦中自动提出的长期能力，必须先有重复证据：在两个或更多项目出现，或在同一项目的至少两个独立开发周期中出现。重复观察同一事件不算重复发生。

然后同时检查：

1. 能写清 trigger、input、output 和 verification。
2. 能说明复用范围、反例与维护成本，且不应由已有项目约定、专家插件或工具承担。
3. 真实运行或行为评估支持收益，不能只依据文档质量判断。

严重事故、高风险外部行为或数据破坏的一次性证据可以先形成项目局部防护；提升为跨项目核心仍需要复用证据，不借此自动扩大作用域。

用户明确提出的能力设计/改造可以直接实现为待验证候选，这不属于自动从一次聊天沉淀规律。报告其验证等级；不能声称已经通过多项目长期验证。

## 提升路径

```text
一次性问题
  -> 当前线程

项目反复出现
  -> Repo Skill / Repo AGENTS / Script / CI

跨项目再次出现
  -> portable core 候选

真实验证有效
  -> portable Skill / MCP

仅对某个客户端成立
  -> reverse-domain client extension
```

## 降级或删除

出现以下情况时，优先删除或降级：

- 新模型已经稳定覆盖，Skill 只剩通用提示。
- Skill 触发频繁但很少改变结果。
- 规则与其他层重复并产生冲突。
- adapter 误拦截成本高于保护价值。
- 脚本维护成本超过它减少的重复劳动。
