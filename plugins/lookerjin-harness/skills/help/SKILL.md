# Harness Help

回答用户怎样使用当前安装的 Harness。用户直接描述目标即可，手动调用技能是可选方式；帮助不是每个任务的前置步骤。

## 通用入口

日常只介绍两种用法：问用法由本技能回答；直接说目标由最合适的现有技能处理，跨步骤任务才进入 Engineering Run。用户无需记住全部技能名，也不必先打开帮助。用户主动选择某个专业技能时保留直接入口，不强制绕回总控。

自然语言是各客户端共用的入口。介绍手动操作时，只有宿主实际暴露了技能菜单或斜杠命令，才给其真实展示名称与语法。没有这些界面时，继续自然语言路径；不要求用户挑客户端、不虚构短别名，也不靠隐藏其他技能缩短入口。

## 先定位问题，再读必要事实

1. 从用户问题和已有对话判断：初次使用、某个场景该怎么开始、当前运行为什么这样做，还是调用/安装问题。已有场景就直接回答；只有缺失信息确实改变建议时才问一个聚焦问题。
2. 以当前安装资源为准。需要找能力时，只查看本技能相邻目录的 `SKILL.md` 名称和 description，再读取最相关技能及必要引用。不要全量加载技能正文，也不要维护第二份固定技能清单。插件源码存在不等于宿主已发现它；MCP 配置存在不等于连接可用。
3. 框架问题先读 [Engineering Run](../engineering-run/SKILL.md)，再按问题读取其中的生命周期、协作或连续性引用。具体技能的现有说明决定其行为，不凭名称或旧版本记忆补全规则。资源缺失则明确未确认，不用联网安装来补齐一次帮助回答。
4. 只有当前项目状态影响答案时，才检查有关规则、检查点或验证入口。通用用法问题不扫描业务仓库；解释运行原因时区分记录中的事实与推断。

## 根据当前能力加载

- 宿主已发现技能：使用其提供的技能调用或资源读取能力。
- 宿主没有专用技能调用工具，但已安装文件可读：从已知安装目录读取对应 `SKILL.md`，相对引用按该文件所在目录解析，按需执行文中公开脚本。不能把读文件说成已注册菜单或安装插件。
- 只有仓库源码可读：可以据此解释用法，说明依据的是源码；是否已在宿主启用仍未确认。
- 连所需资源也不可读：明确缺少的技能文件或访问能力。只在这确实阻塞用户任务时请求最小信息；不自动安装或生成另一套客户端配置。

`agents/openai.yaml` 等展示信息只是相应宿主的增强。核心用法以 `SKILL.md` 为准，不要求其他客户端识别它们；也不要求存在固定名称的 Skill、MCP 或子 Agent 工具。

## 给用户可直接使用的答案

先回答问题，再给一个推荐路径及简短理由；必要时补一个有实际区别的备选。通常提供一条可直接发送的自然语言示例和所依据的技能/文档位置，不默认列出整个目录。用户明确要全貌时再展开。

- 初次使用：说明“目标 + 必要约束 + 完成标准”即可开始，给与其场景相关的例子。不要求先学会技能名、选阶段或运行 setup。
- 阶段问题：解释哪些阶段需要、哪些已有事实足够所以可跳过、何时回退；这些是路径建议，不宣称执行已发生。
- 协作问题：说明用户可以随时纠正方向、限制为只讨论、提供观察或接手小动作；Agent 应解释最小协助请求的目的，同时推进独立工作。
- 调用问题：先核对宿主的实际技能列表和调用方式。名称按宿主展示使用，不臆造 alias，不承诺裸 `/help` 会进入本技能；它可能是客户端内置帮助。宿主不明时优先给自然语言，不为此强行追问客户端。
- 维护问题：区分使用项目、检查插件、评估方法和改变方法。说明私有演化需要用户明确要求；询问演化怎么用本身不是启动演化。

## 帮助与执行的边界

单纯询问“怎么用 / 选哪个 / 为什么”时，只做必要的只读检查和解释，不运行所推荐的工作流，不改文件、安装、创建索引或启动子 Agent。若同一请求已经明确要求执行具体工作，解释必要用法后交给对应现有技能继续，沿用已有授权，不要求用户重复发送示例提示词。这里不新增调度流程。

用完整请求和已有对话判断意图，不按“怎么”或“帮我”等词机械路由：“解释一下然后直接改好”需要继续执行；“先讨论，不要改代码”只推进讨论；用户在已授权任务中问进度，简答后继续原任务。缺少斜杠命令不构成停止理由。

不承诺自动触发必然成功，不把小任务包装成长流程，不把代码地图或任何外部工具当成必装条件。给出的下一步应比用户自己翻目录更省事。
