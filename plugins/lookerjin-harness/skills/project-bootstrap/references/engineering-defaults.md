# 项目可选用的工程默认值

本文件是生成项目 `AGENTS.md` 时的唯一素材来源。按项目裁剪，不要原样整份贴进每个仓库，也不要在模板里再维护一份。

这些规则只有写入目标项目后，才会在该项目的日常任务中生效。

## 基本原则

- 先理解当前任务直接相关的代码、文档、配置和调用关系，再修改。
- 使用完成当前任务所需的最小上下文，不无条件读取整个仓库、全部历史或全部资料。
- 低风险、可逆、局部的不确定性可以采用合理临时假设继续，并明确说明。
- 关键判断如果能通过低成本实验验证，优先实验而不是长期停留在推测。
- 不把构建成功、语法检查通过或 HTTP 200 单独当成功能完成。
- 没有实际运行的验证必须明确标记“未运行”。
- 验证分等级：替身测试（mock/fake/miniredis/sqlmock）、进程级探测、真实外部依赖。替身通过不能标成外部边界已验证。
- 采纳依赖后检查锁文件与语言版本是否被抬升；抬升必须是显式决策。
- 第三方客户端的重试、超时和连接池要显式配置，不要默认继承库的激进重试。这与上面的 Agent 重试政策不是同一层。
- 不做与当前任务无关的重构、批量格式化、依赖升级或目录整理。
- 优先复用项目已有的 Makefile、脚本、CI、测试入口和项目约定，不创建平行体系。
- 默认使用成熟、活跃、可维护的第三方依赖；关键依赖需要核对当前文档和最小验证。
- 能靠确定性机制保证的安全约束，不只依赖模型自觉遵守。

## 重试与人工协助

- 不把“AI 必须独立完成全部工作”当作目标。Agent 应自主完成合理范围内的工作，并在外部边界处及时请求最小人工协助。
- 普通可恢复失败最多尝试 3 次；同类失败连续出现 2 次后应重新判断根因，而不是不断更换调用方式重复碰撞同一边界。
- 权限不足、平台能力缺失、安全策略拒绝、登录/OAuth、需要用户身份或其他明确外部边界，确认一次后应停止盲目重试。
- 不为了避免请求用户协助而设计明显更复杂、风险更高或维护成本更大的绕路方案。
- 请求用户协助时应明确给出：当前阻塞点、已经验证过什么、用户需要执行的最小具体动作、完成后 Agent 将继续做什么。
- 用户协助应尽可能局部；不要把仍可由 Agent 完成的剩余任务整体转交给用户。
- 评估人工成本时同时考虑用户视角：对 Agent 很复杂的事情，对用户可能只需要一次复制、粘贴、点击、授权或提供一个值。

## 外部影响

执行以下动作前，必须获得明确确认：

- 删除重要数据或难以恢复的文件。
- 覆盖难以恢复的内容。
- 生产环境、生产数据库和正式发布操作。
- commit、push、创建/合并/关闭 Pull Request。
- 发送邮件、消息、评论、第三方表单或其他以用户身份对外操作。
- 财务操作或其他不可逆外部行为。

本地只读检查、临时代码实验、可通过 Git 恢复的工作区修改可直接执行。

## 编程

- 修改前理解当前任务涉及的文件、调用关系和现有风格。
- 行为变化、容易回归的问题或已有测试体系明确覆盖的功能，应补充有价值的测试。
- 不为形式完整添加低价值测试。
- 实现后尽量完成：实现 → 运行 → 检查结果 → 修复 → 再验证。
- 发现无关历史失败时记录，不顺手修复，除非它阻塞当前任务。

## Git

- 开始修改前先看工作区状态，保护用户已有修改。
- 未经要求不创建分支、提交、推送或 PR。
- 提交前检查实际 diff 和未跟踪文件。
- 不使用 `git add .` 作为默认提交策略。
- 不改写远端历史。
- 提交信息不加入 AI 署名。

## Harness

- 项目始终成立的规则放项目 `AGENTS.md`。
- 特定任务流程放 Skill。
- 可确定性执行放 Script / Makefile / CI。
- 项目事实放 Docs / code / config。
- 当前工作状态放 Issue / PR / Roadmap。
- 外部系统和当前外部知识通过 MCP / Plugin / Web 获取。
- 客户端特有 Hook、Command 或权限配置不要写成跨平台标准。
- 不创建重复的 source of truth。
