# Project Verification Recipe

这是编写配方的检查项，不是直接复制到目标项目的占位模板。每个命令、路径、输入与断言应来自项目实际证据；不能确认的前提明确标注。

## 身份与边界

说明目标应用、版本/源码状态、实际入口、本次范围及外部依赖。若是 Skill，description 指明应用、入口和触发场景。

## 前提检查与 Launch

列出真实运行目录、构建/启动命令、必要环境变量名称（不记录值）、数据前提和就绪条件。先确定正在驱动正确实例，不能用共享端口已有响应证明本次新代码就绪。

一次性 CLI/公开 library 调用不必启动常驻服务。长驻实例记录自己的 PID/句柄与临时数据位置，明确退出方式。

## Drive 与 Observe

用表或已有用例描述当前关键路径：

| 路径 | 前提/输入 | 真实入口动作 | 预期返回与副作用 | 证据 |
|---|---|---|---|---|

填写正常路径、与任务相关的失败路径和状态变化；调用用户入口或公开 API，不用内部 setter 或测试专用端点代替用户行为。优先稳定语义选择器/命令与项目已有 harness。

HTTP 检查内容、状态转换和副作用；CLI 检查输出、退出码和文件等结果；library 调用公开 API 并核对结果；UI 检查操作与操作后的状态。外部依赖未真实连接时单独注明替身覆盖范围。

## 证据与 Cleanup

给出日志、结果、截图或状态快照的存放方式，证据在清理后仍能查看。记录 [execution-contract](../../engineering-run/references/execution-contract.md) 所需字段。

只回收本次创建的资源；保留用户已有数据与共享实例。发生 Drive 失败也执行 Cleanup，再次运行前检查状态或重置自己的实例。

## 已知限制

列出无法到达的入口、必要凭证/平台和未验证项。说明配方维护位置，避免再创建第二套启动或验证事实。
