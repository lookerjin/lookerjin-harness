# 按需形式化检查

仅当状态空间、并发协议或高影响不变量值得成本时使用；具体建模器与运行器由可用专业能力提供，Harness 不内置模型检查引擎。

- 从真实入口和状态写入代码提取最小模型：状态、动作、原子步骤、环境假设、不变量/活性性质，以及每项到代码的映射。人工理想模型不能证明当前实现。
- 固定工具版本、运行命令、边界、调度/公平性等假设，保留原始输出。未实际运行写 draft / NOT_RUN；工具 exit 0 的含义必须核对，有的检查允许预期反例。
- 加负对照：有意破坏对应性质的隔离模型或历史缺陷必须产生预期反例，证明断言确实有辨别力；不修改生产状态来做负对照。
- 有反例时保留可重放轨迹，并尽可能从产品真实入口复现；不能复现则区分模型缺陷、抽象差异和实现风险，不把模型轨迹说成产品实跑。
- 维护时对比成功同步基线后的相关代码、新写入者和假设，更新模型或实现后复跑原性质、负对照及相关实际入口。阻塞时不推进同步基线。

报告分开说明：模型在给定边界内满足什么、真实产品观察到什么、哪些路径/活性/环境未覆盖。图只是帮助读轨迹，不能替代原始检查证据。
